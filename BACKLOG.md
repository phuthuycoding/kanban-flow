## P1 — Trust & evidence

- [ ] **`kf` runs the test command itself to verify evidence.** Today the CLI only checks the artifact contract (the file exists, the status is valid, the execution id matches) — a dishonest agent can still fabricate a PASS report. Sketch: `kf test --run "<cmd>"` runs the real command and records the exit code plus an output hash in the report, or `kf stage` cross-checks a command log. Scope it narrowly — decide how far the agent is trusted first. **Not started, and the reason is a question for the owner rather than effort:** for `kf` to run the tests means executing a command taken from an artifact — a file the agent writes itself. That is a clear privilege-escalation path: anyone who can edit an artifact can run arbitrary commands as the user. A safe version pins the command in `.kf/config.json` (written by a human, not editable by the agent) instead of reading it from an artifact — and that is a different design from the sketch above. **The owner needs to pick the direction first.**
- [x] ~~**Secret scan upgrade** — the formats half.~~ Four patterns added: three-segment JWT, Slack webhook, Discord webhook, and connection strings carrying a password. Zero false positives across 206 real files in this repository, with a test holding the line. It produced a classification rule now written into the code: **high-confidence if and only if the pattern carries a prefix only a real credential has** — so a connection string is *not* high-confidence, because an honest template has the same shape. Six mutants, none surviving.
- [ ] **Secret scan: an entropy check for `KEY=value`** — the other half of the item above, **deliberately not done**. It changes the scanner's nature from "recognise a known shape" to "guess statistically", and would fire on commit hashes, base64 of a small image, and checksums. It needs a real corpus to calibrate the threshold before being switched on; without that, people learn to `--force` past the gate, which is worse than not having it. Condition to start: the first real miss that an entropy check would have caught.

## P2 — Workflow gaps

- [ ] **An async bridge between agents.** Harness v1 runs synchronously under main. When main is no longer alive (Devin runs for an hour before reporting back), it needs an inbox file plus a way to wake the other CLI on the pinned session (bash prototype in `test-plan/bridge` over in moigo). It would build on the existing `harness.runners` and `sessions`; mind the hop limit to prevent loops. **Deliberately held (rule 7 — do not build for a need that has not appeared):** harness v1 is synchronous and no use case so far needs async. **Condition to start:** a real stage that must outlive the main session.
- [ ] **`kf supersede <old> --by <new>`.** Link two work items that replace one another instead of only recording prose in `kf cancel`; it would make "what replaced this idea" traceable. **Deliberately held (rule 7):** `kf cancel --reason "superseded by X"` already records the relationship in words, and **nothing reads a structured link** today. **Condition to start:** something that genuinely walks the replacement chain (a report, the dashboard) — structure beats prose only then.
- [ ] **`kf run --task "<description>" --out <file>`.** Ad-hoc work outside the six stages (for example "survey three libraries and compare them" before planning). It needs a design for the output path and for how `runs[]` records work that belongs to no stage. **Deliberately held (rule 7):** there is no real use case outside the six stages yet, so adding it now guesses the shape of a need that has not appeared — and the item itself admits "needs a design for the output path and runs[]", which is to say the shape is unknown. **Condition to start:** a specific ad-hoc job that has to be done twice or more.
- [ ] **Harness: verify resume for gemini/opencode.** `gemini -r` takes `latest` or an index; whether it takes a UUID is unknown. `opencode run -s <id>` exists, but how to obtain the id is not established. With a login, add `resume` to the preset. **An agent cannot finish this alone:** it needs those CLIs installed to try `-r` with a UUID; guessing the behaviour and writing it into a preset is worse than leaving the field out. **Partially resolved 2026-09-23 by reading `--help` only, no quota spent:** `gemini` does have `--session-id <UUID>` ("start a new session with a manually provided UUID"), which is exactly the `session: "provided"` shape claude uses and the current preset does not; `-r` still documents only `latest`/index. `opencode` has `-s, --session <id>` to continue, so the current preset — which has no `resume` at all — always starts fresh. **Still needs one real run of each** to confirm whether `gemini -r` accepts a UUID and where `opencode` reports its session id.
- [ ] **Use the harness for real on a repository.** Turn on `harness.stages` with two roles on different models and run a whole feature through, to learn what the role table should contain and what it actually costs. **An agent cannot do this alone:** it needs real agent runs on two different models, which spends the owner's API budget, and the owner picks the repository.
- [ ] **Locking for concurrent agents.** The file-based state has no lock — two agents touching one feature would trample each other. Single-flow today so it does not hurt; when multi-agent work arrives, add `.kfw.lock` plus stale-lock detection. **Deliberately held (rule 7), as the item itself says:** the harness is synchronous, so two agents cannot yet touch one item. Building a lock now adds a subsystem (stale detection, stealing, recovery) for a race that does not exist. **Condition to start:** together with the async bridge — the two belong together, because async is what creates the race.
- [x] ~~**Adversarial validation for bug review.**~~ Added to `kanban-review`: every bug review must state **reachable regressions** (what else calls the changed code, and for each path whether it was checked — "no regressions" on its own is not accepted) and **disproved claims** (at least one assertion by the implementer that the reviewer tried to break and could not; re-run the reproduction rather than trust the report; verify a comment that carries the argument rather than read it). Plus a rule: a passing test does not prove it would fail without the fix — remove or invert the predicate and confirm a test goes red; if none does, that is itself a finding. `kanban-bug` was updated to match: list sibling entry points at triage, because review will ask.
