# install

## Purpose
Put the kf skills and agents where the AI runtime reads them — for every project on the machine (global), for one project, or for one workspace folder, where `/kf:*` is available when Claude Code is started in that folder (Claude Code only) — and take them off again. On a terminal, each choice the person left out is asked one step at a time and nothing changes before they confirm.

## Current behaviour
- **What is installed.** The 11 skills and 7 agents kf manages. `claude` (the default agent) gets the `kf` plugin: `claude plugin marketplace add <package root>`, then `claude plugin install kf@kanban-flow --scope user|project|local`; the commands are `/kf:<name>` and the agents `kf:<agent>`. Every other runtime (`codex`, `gemini`, `kiro`, `cursor`, `opencode`, `devin`) gets rendered `kf-<name>` skill copies in its skills dir (`.agents/skills` for codex) and, when it has an agents dir, the agent files: linked at global scope, copied at project scope (copied too when the package runs from the npx cache or a symlink is denied). Skill copies are always copies, never links. A file of yours at a managed name is left alone and named.
- **Scopes.** `global` is the plugin's `user` scope and the `~` dirs; `project` is the plugin's `project` scope and the `{root}/` dirs; `workspace` is below. The scope comes from `--scope global|project|workspace`, `--global` or `--project`, else `skills.scope` of the effective config (see config-layers), else `global`. `skills.scope` itself accepts only `global` and `project`. A flag the code refuses exits with the message and changes nothing: `--global and --project cannot be combined`, `--scope '<x>' conflicts with --global|--project`, `--scope must be "global", "project" or "workspace", got '<x>'` (there is no `--scope all`).
- **Project scope.** Needs a `.works/`: without one `kf install` exits 1 with `No kanban project found at <dir> (missing .works/) — run: kf init` (stderr `not a kanban project`). It never touches the `~` dirs. `kf uninstall --scope project` outside a project falls back to the working directory. Global needs no project.
- **Global install cleanup.** For the non-Claude agents, a global install also removes kf's copies from the project's skills and agents dirs, unless the project declares `skills.scope: "project"`. A `--scope` that differs from the declared scope prints `Note: installed at scope "<s>" while this project declares "<c>" — both scopes may now hold skills.` The Claude project-scope plugin is not removed. After a successful install, entries of the pre-plugin releases that kf owns (`kanban-*` skills, loose agent files) are removed at that scope; yours are kept and named, and all stay in place when any part of the install failed.
- **Plugin handling.** The plugin step writes only what differs: missing → marketplace add and install; disabled → enable (and repoint the marketplace when it reads another folder); marketplace reading another folder → repoint; version behind the package → `marketplace update` and `plugin update`; source unknown or already current → left as it is. A `claude` that is missing from PATH, answers badly or does not finish in 60 s makes the command exit 1 with the `/plugin marketplace add` and `/plugin install` steps to run by hand; the other agents still install.
- **Linked worktree.** A global or workspace install is refused (exit 1, "run it from the primary checkout") when kf runs from a linked git worktree of the package, since the registration would dangle once it is removed. Project scope is unaffected. `KF_ALLOW_WORKTREE_LINK=1` lifts it for development.
- **Workspace scope (Claude Code only).** The workspace folder is the nearest folder holding `.kf/workspace.json`, searching the working directory and then its parents (the home directory is skipped); else the working directory, when it is outside a kanban project (no `.works/`) and not home; else the scope is refused. `kf install` runs `claude plugin install kf@kanban-flow --scope local` in that folder, so `/kf:*` exists only when Claude Code is started there, and writes `.kf/workspace.json` (`{}`) only after the plugin install succeeded and only when the folder had none. `kf uninstall --scope workspace` runs `claude plugin uninstall kf --scope local` there and never creates the file. The result names the folder (`✓ Workspace folder: <folder>`). Refused with exit 1 and nothing changed: another agent (`workspace scope supports claude only — drop <ids> from --agent or pick another scope`), and a project with no `.kf/workspace.json` above it (`no .kf/workspace.json above this project — run kf install from the workspace folder`).
- **User-scope plugin next to a workspace install.** Once the workspace install succeeded, and never before, the user-scope plugin is removed when the onboarding got a Yes; when that removal fails, the command exits 1 with the `claude` error while the workspace install stays. When the question was not asked (no terminal, every choice given, or `claude` could not be asked during the onboarding, in which case the removal step is skipped) and kf is also installed at user scope, the output instead says `Note: kf is also installed for every project (user scope), so /kf:* still appears outside <folder> — remove it with: kf uninstall --global`. After a No, nothing is printed. When that check itself fails after the install, the output says `⚠ Could not check for a user-scope kf install — <reason>` and the install still counts.
- **Marketplace.** Removing the plugin at any scope keeps the `kanban-flow` marketplace while `claude plugin list` shows a kf install anywhere (user, project, or `local` in any folder), and says so: `· Claude Code: marketplace kanban-flow kept (kf still installed at <where>)`. The last install takes it with it. A plugin or marketplace already gone is a note, not a failure.
- **Uninstall.** Removes the managed skills and agents at that one scope: the plugin for `claude`, the `kf-<name>` copies and agent files for the others. A kf-named entry that is not kf's is kept and named. A shared dir stays while another runtime the project declares in `agents` still reads it. It is idempotent (`already clean`). A global uninstall adds `Global skills are shared by every project — other projects lose them too.` and every run ends with `CLI still on PATH — unlink with: npm rm -g @phuthuycoding/kanban-flow`.
- **`--purge`.** Also deletes `.works/` and `.kf/` under the project root (the working directory when there is no `.works/`), never anything under `docs/`, and leaves `.gitignore` alone, saying so. Without a terminal it refuses without `--force` (`Refusing to purge project data (...) in <root> without confirmation — re-run with --force.`, exit 1); on a terminal it asks first, and `--force` skips the question.
- **Onboarding.** Applies when stdin and stdout are both terminals and a choice is missing. The choices are agents (`--agent`), scope (`--scope`, `--global`, `--project`) and, for uninstall, purge (`--purge`); `--force` is not one. Every choice given, or no terminal: nothing is asked and the command runs as it always did. `kf install` with a given scope it cannot use (`project` outside a project, `workspace` with no folder) asks nothing either and prints the refusal above; so does `kf uninstall --scope workspace` with no folder or with an agent other than `claude` given. Only the missing steps are asked, in the order agents, scope, purge, confirm, each labelled `Step n/N` with N counting just the steps asked. Arrow keys move, digits 1-9 move the cursor, Enter accepts, Space toggles in the agents list; a row marked unavailable shows its reason and cannot be accepted — Enter on it prints that reason under the rows. A prompt redraws in place even when a row is wider than the terminal and wraps.
  - **Agents.** A checkbox of every runtime, `claude` preselected. Enter with none selected stays and shows `Select at least one agent (Space toggles).`
  - **Scope.** `global`, `project`, `workspace`, with the scope the plain command would use preselected; the workspace row reads `workspace — Claude Code, only when started in <folder>`. For install, `project` is unavailable outside a project (`no .works/ — run kf init`); uninstall keeps it. `workspace` is unavailable when any selected agent is not `claude` (`workspace scope supports claude only`) or no folder resolves (the reason above).
  - **Install.** With no choice given, a first unnumbered `Setup mode` step: `Quick — claude, scope <s>` installs exactly what the plain command does, with no confirm; `Customize` runs agents, scope, then confirm. When the scope is `workspace` with only `claude` and a user-scope install exists, one more step asks `Remove it so /kf:* only appears in <folder>?` (No preselected) before the confirm. While kf checks for a user-scope install it shows `Checking the Claude Code plugin install…` with a spinner; keys typed meanwhile are ignored (they never move the cursor of the step that follows), and Ctrl+C there aborts with nothing changed.
  - **Uninstall.** The purge step (`No — skills/agents only` preselected, `Yes — delete .works/ and .kf/`) is offered only when a `.works/` is found, so a workspace folder holding just `.kf/` is never offered for deletion. With agents and scope given but no `--purge`, a project still gets the purge step and the confirm.
  - **Confirm.** One summary line (`Install claude at scope workspace (<folder>), then remove the user-scope install?`, `Uninstall … and permanently delete <dirs>/?`) with the action or `Cancel — change nothing`. When purge was chosen, or `--purge` was given and another step was asked, this step lists the directories and replaces the separate purge question; with nothing else asked, the plain purge question stays.
  - **Leaving.** Cancel prints `Nothing changed.` and exits 0. Ctrl+C, Ctrl+D or end of input prints `Aborted — nothing changed.` and exits 1 (stderr `aborted`); the terminal is restored either way. Neither leaves a file or a plugin change, `.kf/workspace.json` included.
- **Other readers.** `kf init` installs at the effective scope. `kf autoconfig` and `kf doctor` check the install at the effective scope (`global` or `project`) and name `kf install --agent <id> --scope <scope>` as the fix; they do not look at a workspace install.

## Use cases
- UC-001 Install through the onboarding — Quick, or Customize with agents, scope and confirm.
- UC-002 Uninstall through the onboarding — agents, scope, purge and confirm.
- UC-003 Pass some options — only the missing steps are asked, and nothing when all are given.
- UC-004 Run without a terminal — CI, scripts and agents get no prompt, the same defaults and exit codes.
- UC-005 Install kf for one workspace folder only — `/kf:*` appears only when Claude Code starts there, optionally dropping the user-scope install.
- UC-006 Choose where the skills live — global by default, project as an opt-in; a project install leaves the global one alone, a global install cleans the project's copies.
- UC-007 Remove at a chosen scope — one scope per run, warning when it is shared by every project.
